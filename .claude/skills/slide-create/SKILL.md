# slide-create

Markdownで書かれた「スライドのアウトライン」を、実際のPowerPoint（`.pptx`）に変換するスキル。
`##` / `###` の見出し構造と、`//` で書かれた指示コメント・レイアウト指定を解釈してスライドを組み立てる。

役割分担:
- **このスキル（監督）** … アウトラインを読み、1枚ずつのレイアウトと本文を決めて、生成スクリプトを書く
- **`slides/build/lib.js`（部品）** … デザイン定義どおりの見た目でスライドを描く共通部品（pptxgenjs）
- **`document-skills:pptx`（職人）** … .pptx の読み書き・検証の手順。仕上げの確認や既存 .pptx の編集で使う

## いつ使うか
- ユーザーが `/slide-create` を実行したとき
- 「スライド / 資料 / プレゼン / 勉強会資料を作って」と依頼されたとき
- `slides/outline/` 配下のアウトライン `.md` からPPTXを起こしたいとき

## 参照ファイル（必ず読む）
- `slides/template/_DESIGN.md` … **デザインシステム**。色・フォント・寸法・レイアウトカタログの定義。
- `slides/template/_TEMPLATE.md` … アウトラインのひな形。新規資料を作る依頼のときはこれをコピーして埋める。
- `slides/build/lib.js` … 共通部品。使えるレイアウト関数と引数はこのファイルのコメントを読む。
- `slides/build/example.js` … 生成スクリプトの書き方の見本（`slides/outline/example.md` に対応）。

## 入力
- **引数あり**: 指定された `.md` をアウトラインとして使う（例: `/slide-create slides/outline/my-talk.md`）
- **引数なし**: `slides/outline/` 配下の `.md` を探す（`example.md` は見本なので除外）。
  候補が複数あればユーザーに確認、1つならそれを使う。
- **「テンプレから新しく作りたい」** と言われた場合: `slides/template/_TEMPLATE.md` をコピーして
  `slides/outline/<資料名>.md` を作り、内容を埋めてから PPTX に変換する。
- **ざっくりした台本だけ渡された場合**（スマホから話した内容など）: まず `slides/outline/<資料名>.md` に
  アウトラインとして整理し、ユーザーに構成を見せてから生成に進む。

## アウトライン記法
- `#` … 資料全体のタイトル（表紙）
- `##` … 章。原則1枚のセクション扉スライドにする
- `###` … 個別スライドの見出し
- `- ` / `    - ` … 箇条書き（インデントで階層）
- 表（`| ... |`）やコード（```）はそのままスライドの要素として扱う
- `【】` で囲んだ語 … アクセント色（オレンジ）で強調
- `<!-- ... -->` … HTMLコメントは完全に無視する

### ディレクティブ（`//key: value`）
| キー | 意味 |
|---|---|
| `//layout:` | レイアウトID。`slides/template/_DESIGN.md` の「レイアウトカタログ」から選ぶ |
| `//eyebrow:` | 見出しの上に出る小ラベル。省略時は親の `##` の文字列を使う |
| `//image:` | 画像1枚のパス |
| `//images:` | 画像を複数（カンマ区切り）。`image-3` / `image-4` / `diagram` 用 |
| `//caption:` | 画像下の補足テキスト |
| `//lead:` | スライド上部のオレンジベタ帯に置く1行 |
| `//label:` | コードブロックの見出しラベル |
| `//sub:` | セクション扉・クロージングのサブコピー |
| `//note:` | スライド下部の注釈（`NOTE —` として表示） |

### 指示コメント（`//` のみ）
`//layout:` のようなキーを持たない `//` 行は、**そのスライドに何を書くかの作成指示**。
この指示に従って本文を生成し、指示コメント自体はスライドに出さない。

## レイアウトID → lib.js の関数
| `//layout:` | 関数 | メモ |
|---|---|---|
| `title` | `d.title()` | 表紙 |
| `agenda` | `d.agenda([...])` | `##` を列挙 |
| `message` | `d.message()` / `d.purpose()` | 大きな一言。下に3つの補足を並べるなら `purpose` |
| `section` | `d.section(no, title, sub)` | 章の扉 |
| `closing` | `d.closing()` | 最後の1枚 |
| `bullets` | `d.bullets()` | 箇条書き |
| `image-right` / `image-left` | `d.imageSide({ side })` | |
| `image-full` | `d.imageFull()` | スクショ |
| `image-3` / `image-4` | `d.cards()` | 画像付きカード |
| `two-col` | `d.twoCol()` | |
| `numbered` | `d.numbered()` / `d.cardGrid()` | 説明が長いなら `cardGrid`（白カード） |
| `grid-4` | `d.cardGrid({ cols: 2 })` | 読みやすさ優先。旧デザインは `d.grid4()` |
| `compare-2` | `d.compare2()` | |
| `table` | `d.table()` | |
| `code` | `d.code()` | `side` で行ごとの注釈 |
| `diagram` / 流れ | `d.flowCards()` / `d.flow()` | 矢印でつなぐ |
| （その他） | `d.timeline()` `d.chips()` `d.phoneChat()` `d.quote()` `d.sources()` `d.profile()` | |
| どれにも合わない | `d.custom({eyebrow,title}, (s, k) => {...})` | pptxgenjs で直接描く |

## 手順
1. **`slides/template/_DESIGN.md` と `slides/build/lib.js` を読む**（色・寸法・使える関数を把握する）。
   初回は `node_modules/` があるか確認し、無ければ `npm install` を実行する。
2. **入力アウトラインを読む**（上記「入力」に従い対象 `.md` を確定）。
3. **各スライドのレイアウトを確定**する。
   - `//layout:` があればそれに従う。
   - **無い場合は内容から推定する**: 画像指定あり→`image-right` / 対比→`two-col` /
     手順→`numbered` / コード・ツリー→`code` / 表→`table` / 箇条書きのみ→`bullets`。
4. **各スライドの本文を用意する**。
   - `//` 指示コメントの意図どおりに本文（箇条書き / 図解 / たとえ話）を生成する。
   - 「ツリー図」「構成図」の指示は `code` レイアウトのダーク枠に `├─ └─` で描く。
   - **機微情報の抽象化**: 顧客名・固有の内部情報は伏せ、一般化した表現にする。
   - 公式ドキュメント等の参照指示がある場合は、WebFetch で確認してから書く。出典URLは `note` か `sources` に残す。
5. **生成スクリプトを書く**: `slides/build/<資料名>.js` を作る（`example.js` と同じ形）。
   ```js
   const { createDeck } = require("./lib");
   const d = createDeck({ title: "資料タイトル", event: "イベント名 — 2026.11" });
   d.title({ title: "資料\nタイトル", date: "2026.11.30" });
   // ...1枚ずつ d.<レイアウト>() を呼ぶ
   d.save("<資料名>");
   ```
   - 画像は `slides/assets/` 配下のパスを渡す。**ファイルが無ければ自動でオレンジの仮枠が入る**（処理は止まらない）。
6. **実行する**: `node slides/build/<資料名>.js` → `slides/output/<資料名>.pptx` ができる。
7. **見た目を確認する**（できる環境なら）。
   - LibreOffice があれば `soffice --headless --convert-to pdf slides/output/<資料名>.pptx --outdir slides/output`
     で PDF にし、画像にして全ページを目で確認する（文字のはみ出し・1文字だけの改行・重なり）。
   - 詳しい検証手順は `document-skills:pptx` スキルに従う。
   - 崩れていたら文言を短くする / `size` `cardH` などの引数で調整して、6 に戻る。
8. **完了報告**: 生成したファイルパス、スライド枚数、章立て、未配置の画像（実行ログの「未配置の画像」）、
   `【】` のまま残っている埋め込み欄があればそれも伝える。

## スタイルの既定
- 1枚1メッセージ。タイトルは短く、本文は箇条書き中心。
- 本文は6〜7項目まで。1行は全角30文字以内。超えるなら2枚に分ける。
- **小さく薄い文字を避ける**。説明文は 15pt 以上・濃い色（INK）を基本にし、白カード（`cardGrid` / `flowCards`）を優先する。
- アクセント色を使うのは「見出し罫線 + 強調1〜2箇所」まで。
- 日本語の勉強会向け。堅すぎないトーン。専門用語・コード識別子は原語のまま。
- 図解・たとえ話の指示（例: 「ドラクエで例えて」）は、その比喩を活かして視覚的に整理する。
- 「議論の時間」など文言だけで良いと指定されたスライドは、装飾を抑えたシンプルな1枚にする。

## 注意
- `//` コメントの指示は**作成方針**であり、そのままスライドに載せない。
- `【】` で囲まれたテンプレの埋め込み欄（例: `【資料タイトル】`）が残ったまま生成しない。埋まっていなければユーザーに確認する。
- アウトラインにない章を勝手に増やさない。逆に、指示された枚数は満たす。
- 色・フォント・座標は `_DESIGN.md` / `lib.js` の値を使い、勝手に配色を変えない。
